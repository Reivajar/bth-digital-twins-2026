Start here: your first change with AI, step by step

You do not need to know how to code, or to have used an AI assistant before. Follow the steps in order. The first time takes about 30 minutes.

  • You needYour own laptop, Windows or Mac
  • BrowserChrome or Edge (Safari and Firefox may also work)
  • AI assistantCopilot with your BTH account, or another one you like
  • InternetOnly for the AI chat. The map works offline

1Unzip the kit

You downloaded a file called helsingborg-starter-kit.zip. A zip file is a packed folder. You have to unpack it before anything works.

Windows

  1. Open your Downloads folder.
  2. Right-click helsingborg-starter-kit.zip and choose Extract All…, then Extract.
  3. A normal folder called helsingborg-starter-kit appears. Move it to your Desktop.

Mac

  1. Open your Downloads folder in Finder.
  2. Double-click helsingborg-starter-kit.zip.
  3. A normal folder called helsingborg-starter-kit appears. Move it to your Desktop.
Do not work inside the zip. If you open files directly from the zip, the map stays blank and nothing you save is kept. Always work in the unpacked folder.

Inside the folder you see index.html (the map), this guide, and the folders data, lib and docs. Never move or rename those folders: the map needs them next to it.

2Open the map

  1. Double-click index.html. It opens in your web browser.
  2. If it opens in a text editor instead (lots of code), close it. Right-click the file, choose Open with, then Chrome or Edge.
Check: you see 3D buildings of central Helsingborg, and a panel with a slider. Move the slider: the number under Result changes. Click a building: its details appear under Selected building. To tilt or turn the map, hold the right mouse button and drag (on a trackpad, hold Ctrl and drag).

If the page is blank, see When it breaks. If it still does not work, email Javier. You can carry on with the next steps anyway.

3Make file endings visible

File names have an ending after the dot, such as .html or .txt. Your computer usually hides it, and that causes the most common mistake: saving v1.html.txt by accident. Turn the endings on once.

Windows 11

  1. Open any folder (File Explorer).
  2. Click View, then Show, then tick File name extensions.

Mac

  1. Click on the desktop so Finder is active.
  2. Menu Finder, then Settings, then Advanced. Tick Show all filename extensions.

4Open your AI assistant

An AI assistant is a chat: you type a request in plain English, and it writes an answer, including code. Any assistant works. BTH students have Copilot through their university account.

Copilot with your BTH account

  1. In Chrome or Edge, go to m365.cloud.microsoft/chat. If BTH has given you a different Copilot link, use that one.
  2. Sign in with your BTH student account, the same one you use for email and Canvas.
  3. Check that your BTH account is shown at the top right, so you use BTH's licence and not a private account.

Or another assistant

Claude (claude.ai) or ChatGPT (chatgpt.com) also work, with a free account. The steps below are the same.

Words you will see: a prompt is the message you type. A new chat starts a conversation from scratch (button at the top or side). Attach (a paperclip or + next to the message box) sends a file along with your message.

5Your first change

You will ask the AI to change the map, save its answer as a new file, and open it. One round looks like this:

  1. Attach your latest file
  2. Say what to change
  3. Download or copy the file it returns
  4. Save it in the kit folder as the next number
  5. Double-click to check
One folder for everything. Every file you save or download goes in your unzipped kit folder, next to index.html and the lib and data folders. Not in Downloads, not on the Desktop, not inside the zip. The map only works there, because it loads the map library from lib and the buildings from data.

Do not use the chat's Preview or Run button. The preview cannot see those folders, so the map fails there even when the code is right. Always save the file and double-click it.

a. Start a new chat and give it the context

Click New chat. Copy the text below with the button, paste it into the message box (Ctrl+V on Windows, Cmd+V on Mac), but do not send yet.

Context, once at the start of every new chat
I am an urban planning student, not a programmer. I am changing a web page that shows a 3D map of Helsingborg with MapLibre GL JS. The page loads its data from local JavaScript files that I must not change. The buildings are in a GeoJSON variable called BUILDINGS. Each building has these properties: id, height_m (number), height_source (text), floors (number or null), use (text), ground_m (number, ground elevation in metres above sea level, approximate), model_checked (year, a number), source (text). There is also WATER and PARKS. Keep the page working by double-clicking the file, with no server and no new libraries from the internet. Keep the panel section "What this does not show" and keep my comments. Every time, return the entire file as a downloadable .html file, and also show the complete code in one code block, from <!DOCTYPE html> to </html>. Never return only the changed part.

b. Attach the map file

Click the paperclip or + next to the message box and choose index.html from your kit folder on the Desktop. Attach only this one file.

Never attach or paste the files in the data folder. They hold thousands of buildings and are far too large for a chat. The AI only needs to know what one building looks like, and the context text above already tells it.
My assistant has no attach button

Then paste the code instead. Open index.html in a plain text editor (see step d for how), select everything with Ctrl+A (Mac: Cmd+A), copy, and paste it into the message box under the context text. If the chat says the message is too long, try another assistant.

c. Say what to change, then send

Under the context, paste this first exercise and press Enter or the send arrow.

First exercise
Change the slider so it highlights buildings lower than the chosen height instead of taller. Update the text in the panel to match. Return the entire updated file as a downloadable file named v1.html. Also show the complete code in one code block, from <!DOCTYPE html> to </html>, with nothing left out.

Wait until the answer has finished. Depending on the assistant, you get a download link or file card, a long block of code in a grey box with its own Copy button, or both.

Check the answer is complete: scroll to the end of the code box (or open the downloaded file in your text editor). It must end with </html>. If it stops in the middle, or says something like "rest of the code unchanged", reply: "Give me the complete file, from <!DOCTYPE html> to </html>, with nothing left out."

d. Save the answer as a new file, v1.html

Whichever way you get it, the file must end up in your kit folder, next to index.html, named v1.html. Do not overwrite index.html: it stays as your safe original.

If there is a download link: click it. The file usually lands in your Downloads folder. Move it into the kit folder and check that its name ends in .html (rename it v1.html if needed). A file left in Downloads shows the map without buildings.

If there is only code, or the download does not work: click the Copy button on the code box and paste it into a new file with a plain text editor:

Windows: Notepad

  1. Open Notepad (search for it in the Start menu).
  2. Paste with Ctrl+V.
  3. File, then Save as. Go to the kit folder on your Desktop.
  4. Set Save as type to All files, type the name v1.html, and keep the encoding UTF-8. Click Save.

Mac: TextEdit

  1. Open TextEdit and choose New Document.
  2. Menu Format, then Make Plain Text. This step matters.
  3. Paste with Cmd+V.
  4. File, then Save. Name it v1.html, choose the kit folder, encoding UTF-8. If asked, choose Use .html.

If you already use VS Code or another code editor, that works too: new file, paste, save as v1.html in the kit folder.

e. Open it and check

Double-click v1.html. Move the slider: it should now highlight the lower buildings.

It works? Well done: that is the whole method. Write one line in your group's build log: what you asked, what happened, and that it became v1.html.

6Keep going: one change per round

  1. In the same chat, attach your latest working file (now v1.html) and ask for the next change.
  2. Save each answer under the next number: v2.html, v3.html, and so on, always in the kit folder. In the prompt, change the file name in [brackets], such as [v2], to your next number.
  3. Ask for one change at a time, in concrete words: "add a slider from 0 to 5 m", not "make it better".
  4. If the chat gets long and the AI starts forgetting things, start a new chat: paste the context again and attach your latest file.
  5. Take turns at the keyboard in your group, and log every round.

Try breaking it on purpose once: ask for something vague, such as "make it look better", and see what happens. Then go back to your last good number.

When you are ready, use the starting prompts below.

7When it breaks

It will break. That is normal, and what went wrong is useful for your specification.

The AI does not give you the file you asked for

Sometimes the assistant misbehaves: it returns only a piece of the code, says "the rest stays the same", describes the change in words, or promises a file and never makes one. Sorry: some AI tools are simply clumsy at this. It is not your fault. Try these, in this order:

  1. Copy and paste it yourself. If the full code is in the answer, copy it and paste it into a new file in Notepad (Windows) or TextEdit in plain text mode (Mac), then save it as v1.html in the kit folder. See step 5d.
  2. Repeat the instruction. Reply: "Give me the entire file, from <!DOCTYPE html> to </html>, with nothing left out."
  3. Ask for a link. Reply: "Create the complete file as a downloadable .html file and give me the link."
  4. Say the goal more clearly. A vague request gets a vague answer. Say what the user should see and do, which field to use, and what must not change.
  5. Start again. Open a new chat, paste the context again and attach your latest working file. If it still fails, try another assistant.

Note in your build log which of these you needed. It tells you something about the tool.

★Starting prompts

Basic examples to learn with. Each replaces the worked example on the map. Start a round with one of these, then change the words in [brackets] to make it yours. Your group's own function, agreed on Wednesday, can grow out of one of them, or not.

A. Sea level and buildings

Prompt A
Replace the height function with a sea-level function. Add a slider for water level from 0 to 5 metres in steps of 0.25. Colour buildings whose ground_m is below the chosen level blue and all others light grey. Show the number of affected buildings in the Result section. Update the Function text to: "The tool shall show which buildings stand on ground below a user-selected water level." Return the entire updated file as a downloadable file named [v2].html. Also show the complete code in one code block, from <!DOCTYPE html> to </html>, with nothing left out.

What you will find: ground_m comes from a coarse 30 m grid that partly includes rooftops. Look at which buildings it gets wrong. That is a data finding for your specification.

B. Where the model is out of date

Prompt B
Replace the height function with a model-currency function. Colour buildings by model_checked: before 2015 dark red, 2015 to 2019 orange, 2020 or later green. Add a slider "Show buildings not checked since [year]" from 2010 to 2026. Show the number of buildings not checked since the chosen year. Update the Function text to: "The tool shall show which parts of the city model have not been checked against reality since a user-selected year." Return the entire updated file as a downloadable file named [v2].html. Also show the complete code in one code block, from <!DOCTYPE html> to </html>, with nothing left out.

What you will find: model_checked is invented. No public data says when each building in Helsingborg's model was last updated. Your specification has to say who would record it, and how.

C. Massing sketch

Prompt C
Add a sketch tool. When I click "Start drawing", each click on the map adds a corner of a new building footprint, and "Finish" closes the shape. Add a number box for height in metres. Show the new building in 3D in a bright blue colour among the existing buildings. In the Result section, show the height of the tallest existing building within 50 metres of the new one, and the difference. Return the entire updated file as a downloadable file named [v2].html. Also show the complete code in one code block, from <!DOCTYPE html> to </html>, with nothing left out.

What you will find: many neighbour heights are estimated. Click them to see height_source. A height comparison is only as good as that field.

Your own function

Write your function as one sentence starting with "The tool shall". Then:

Your own
Replace the height function with this: [your sentence]. Use these fields: [fields from the list in the context]. Keep everything else on the page. Return the entire updated file as a downloadable file named [v2].html. Also show the complete code in one code block, from <!DOCTYPE html> to </html>, with nothing left out.

If no field in the data supports your function, that is a finding. Ask the AI to create clearly labelled invented data, and say so in Annex A of your specification.
